- **Resumed Physical Playback Baseline (`6b986ce` / `6c2fb35`, 2026-11-18 evening)**: Ordinary Windows WASAPI audio was heard continuously on the real iPhone (`Có tiếng, nghe liền mạch`) over a bounded 60-second run (`32/32` physical checks, `6,000` PCM frames, zero sampled receiver gaps/overflow/silence/sender drops, RSS `12.48–12.57 MiB`, app gain `0.25`; `17,416` zero-filled capture bytes remained unlocalized; final 120s simulator gate had `9,600` silence bytes before Phase 9's follow-up fix). Evidence: [`resume-validation.json`](reports/resume-validation.json), [`resume-physical-wasapi60.json`](reports/resume-physical-wasapi60.json), [`resume-human-listening.json`](reports/resume-human-listening.json).

- **Historical Physical iPhone 6 Hardware Checkpoint (`0.1.2` / `307e167`, 2026-11-18)**: Before user USB unplug, embedded Agent execution, paired `usbmux` authentication, basic 1 MiB uploads/SHA/range jobs, first 3-second audible fixture speaker confirmation (`Có nghe tiếng`), and stuttered normal WASAPI media (`Có nhưng bị ngắt/giật` + `repairs-physical-wasapi90.json`) were recorded. See [HARDWARE_TEST_RESULTS.md](HARDWARE_TEST_RESULTS.md).
- **Current 0.2.0 Continuation Checkpoint (Linux VM Engineering Environment)**: All Windows Host libraries, Tray UI, Simulator, Chromium extension, MSIX manifest, `36/36` `.NET` socket/hybrid-media/soak checks (`30.15s` concurrent 98-job zero-loss soak in [`hybrid-soak-30s.json`](reports/hybrid-soak-30s.json)), `C11` shared wire/ring tests (`zig cc` & `gcc`), `22/22` Python toolchain tests, `22/22` Clang static analyzer TUs, and `19`-unit ARM64 iOS 12 cross-builds (`BackThread.ipa`) pass. **Because the Linux VM has no physical iPhone 6 or Windows 10 desktop GUI connected, newest 0.2.0 iOS visuals, Phase 9 audio quality on speaker, Wi-Fi `AVPlayer` playback, and live Windows tray/MSIX/Spotify flows remain pending physical hardware acceptance.**
