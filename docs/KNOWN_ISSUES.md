# Known Issues and Limits — 0.2.0

1. **Physical iPhone 6 runtime acceptance for `0.2.0` & Phase 9 fixes is pending cable reconnection.** While `36/36` `.NET` simulator tests (including the 30.15s zero-loss soak in [`hybrid-soak-30s.json`](reports/hybrid-soak-30s.json)) and `22/22` Clang static analyzer TUs pass, acoustic speaker output of the Phase 9 fixes, `BTDirectMediaPlayer` hardware H.264/HLS decoding, and physical touch navigation across the new landscape UIKit views have not been tested on physical hardware since unplug in `0.1.2`.
2. **Windows 10 desktop GUI, Registry & MSIX runtime untested in Linux VM.** `BackThread.Tray.exe`, `Setup-Portable.ps1`, Chromium Native Messaging registry installation (`install-native-host.ps1`), live `UserNotificationListener` consent under MSIX (`packaging/msix/`), DPAPI encryption on live Windows user keys, and real GSMTC app control compile cleanly (`0W/0E`, win-x64 release staged) but require a Windows 10 desktop session for live interactive QA.
3. **YouTube direct-stream playback intentionally unsupported without official embed.** BackThread rejects stream scraping, signature deciphering, and WebView background audio workarounds. YouTube links default to oEmbed metadata + Mode D remote control + Mode C Live PCM, or optional foreground `youtube-nocookie` iframe (`allowExperimentalYouTubeEmbed: true`) which creators can restrict on some videos.
4. **Spotify DRM audio stays on Windows/Connect.** Spotify OAuth 2.0 PKCE controls playback state, playlists, and devices via official Mode D REST calls; DRM tracks cannot transfer natively to iOS `AVPlayer` and require Mode C Live USB PCM to play through the iPhone speaker.
5. **No virtual Windows sound driver / automatic default output switch.** Windows loopback captures the default render endpoint (`WasapiLoopbackCapture`). Switching Windows default audio output endpoints automatically remains out of scope without a kernel virtual audio driver.
6. **iOS background lifetime without active audio/video.** UIKit relies on `UIBackgroundModes=audio`; iOS may suspend the app when no audio/media session is active. Standalone daemon execution (`/var/mobile/BackThread`) remained denied historically (`Killed: 9`), and no `launchd` service is installed.
7. **Text job Unicode whitespace difference.** Native iOS worker `text` jobs count ASCII whitespace, while `.NET` uses Unicode whitespace (intentional lightweight A8 budget; documented portability difference).
8. **Transport confidentiality boundary.** `BTH1` frames use session-establishment HMAC authentication (`256-bit` CSPRNG nonces), not per-packet AEAD encryption; only loopback and trusted physical Lightning USB are supported.
9. **Archives remain opaque.** Uploads/artifacts verify whole-file SHA-256 and store opaque files inside bounded `2 GiB` storage; automatic block-delta sync, archive extraction, and retention policies are not implemented.
10. **Host audio receiver failure & interruption edge cases.** Physical audio-route switching, phone calls, and lock/unlock continuity on iOS 12.5.8 `BTAudioSessionCoordinator` require device execution to confirm alongside the static analyzer pass.
